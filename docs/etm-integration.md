# ETM 执行轨迹：更多功能中的本地工作台

菜单：**更多功能 → ETM 执行轨迹**。ETM完整页面内嵌在工具箱内，保留ELF、断点、时钟、采集、执行流、Timeline、火焰图和源码浏览。

## 启动

推荐从 **工程生成 → ETM 桥** 点击“下载完整 ETM 桥包”。解压整个文件夹，双击 `check-tools.bat` 预检，再双击 `start-etm-bridge.bat`：服务准备就绪后自动打开 ETM 页面。也可用页面的“打开 ETM 工作台”按钮打开已运行的桥。

完整包支持 Windows 64 位，包含 Python、Python 依赖、工具箱/ETM 网页、Kingst 采集分析服务和 OpenCSD 解码器；无需安装 Python、下载两个工程或构建解码器。KingstVIS 及其驱动仍需安装并打开 Socket。包可放在中文或含空格的路径中；端口在 `etm.config.json` 中修改，默认 8878。记录保存在包内 `data/records`，升级前请保留 data。

“仅下载启动文件”提供 BAT、PowerShell、端口配置和说明，适合已有完整包时覆盖同名启动文件。它不包含运行环境；第一次使用请选择完整包。完整包下载时校验 SHA256；仓库中的运行快照、来源清单、许可证和构建方法见 `bridge/etm/README.md`。

ETM的逻辑分析仪采集和OpenCSD解码需要本地服务；串口、RTT、SWO等原有静态网页功能仍可独立使用。

### 开发源码运行（开发者选用）

普通使用无需下面的工具链。开发两个原始仓库时，将更新后的 `web-serial-rtt-tools` 与 `web-etm-trace` 放在同一父目录，在串口工具仓库运行：

```powershell
python -m pip install -r ../web-etm-trace/requirements.txt
pwsh -NoProfile -File tools/dev/start-etm.ps1
```

打开 `http://127.0.0.1:8878/#etm`。两个仓库的目录不相邻时，可传 `-EtmRoot '你的ETM工程路径'`；端口可用 `-Port` 调整。本地启动脚本在缺少解码器时调用ETM工程的构建脚本，需要其CMake/Ninja/MinGW工具链。已经构建好的解码器会直接复用。

普通静态站点的ETM菜单显示本地启动说明；下载并启动完整桥包，再从本地集成入口打开，即可使用同源内嵌和探针共享。

## 操作顺序

1. 启动KingstVIS并打开其Socket接口（默认23367），使能采集所需的五路通道。
2. 从更多功能进入ETM，载入板上同一份ELF，连接探针；首次使用该地址需在浏览器授权并选择akaLinkPro。
3. 搜索函数，点击前面的＋添加断点，选择圆点作为采集起点。
4. 核对目标与时钟，F103ZE当前验收档为CPU48 MHz、引脚TRACECLK24 MHz；HSE按板卡实际值填写，本板为8 MHz。
5. 配置Kingst：CH0～4=PE2～PE6，共地；本板验收为500 MSa/s、10 ms、2.0 V、相位0.25，分支广播关闭。
6. 点击联动采集，完成后查看执行流、Timeline、火焰图与源码；文件页可保存便携记录。

固件负责CPU/外设时钟和业务程序；网页配置ETM/TPIU及Trace引脚、断点和资源恢复。火焰图宽度表示执行序号或路径记录数，不表示函数耗时。

## 探针共享

内嵌ETM复用主工具的USB驱动、USB租约和ProbeManager。连接ETM时先释放冲突的RTT/调试器/SWO资源；正在采集或控制目标时拒绝其它功能抢占。操作结束后，切到其它功能并连接时会先恢复ETM资源并断开它。普通历史浏览不申请探针。

ETM 原始工程仍在 `web-etm-trace` 维护；本仓库 `bridge/etm` 保存受审查的运行快照及下载包。完整包不包含 SDK、编译工具链或用户历史记录，只带一个 Demo。独立ETM页面仍能单独启动。PXLogic实验分支未纳入此集成。

## 当前验收

2026-10-14，F103ZE/Kingst同源集成接口验收：复位采集、不复位再次采集、等待时停止、停止后再采集均通过。三次10 ms窗口恢复174786/174785/174786条指令，全部对应源码，overflow、包错误、未处理字节均为0。首次失败记录保留；当时CH4无跳变，用户重新接好后复验通过。

实板使用项目的持续SWD接口运行实际EtmTarget及主工具ProbeManager，再走同源采集/解码接口；不是模拟Trace数据。菜单、内嵌初始化和历史分析在浏览器验收。物理浏览器WebUSB授权/接口转交尚未由自动化完成：测试浏览器启动被自动审批拒绝，现有浏览器的首次USB选择需用户授权。首次在Chrome/Edge打开时请完成设备选择。

### 1.0.2：嵌入页面的复位与调试口恢复

工具箱探针驱动补齐 `writeMemDiagnostic` 和 `recoverDebugPort`。AIRCR 软件复位等控制写只发送一次，不按普通内存的回读差异再次写入；ETM 拒绝缺少该接口的旧驱动。停在非所选起点时，错误提示包含实际 PC 和 DHCSR/DFSR/DEMCR，目标保持暂停供检查。

F103ZE 实板使用生产工具箱探针 JS，经原始 USB 字节转发验收：从 `cdc_acm_init`（0x080004d0）连续三轮复位/Kingst 采集/解码/恢复断点通过，每轮仅一次复位；500 MSa/s、10 ms、1.65 V、分支广播关闭，172581/172601/172581 条指令，overflow 与包错误均为 0。“运行至起点”另以循环函数 `cdc_poll` 验证命中。调试口恢复没有复位或继续 CPU，PC 保持一致。用户原先停在 UART 初始化入口的错误暂停尚未在验收中复现。

`cdc_acm_init` 属于初始化函数，经过后继续运行不会再次调用；再次从它采集应勾选“先复位，再运行至起点”。更新完整桥包时先退出旧桥进程，保留 `data` 目录，再启动新版并刷新页面；只更新网上静态页不会更新已解压桥包中的页面代码。首次浏览器 USB 授权仍须用户完成。

### 1.0.3：任务与操作顺序回归

离线、并发采集、重复解码、提前取消、请求与阶段超时、文件选择与探针仲裁、记录切换、Windows JSON/索引竞争均增加了回归及修复。停止等待触发时视为取消，不把 LA 上一次的缓存保存为新记录；故障后明确恢复已验证断点。

所选断点是 CPU 的停点，不保证首条恢复指令恰为该断点。本轮 F103ZE 记录初始同步缺口会略过初始化入口，现增加诊断；耗时与完整覆盖率百分比尚未实现。200M 取样相位0.25失败、0.10的2/5 ms复测通过；默认继续保持已验收的500M/0.25。详细功能边界及失败证据见 [ETM审查与验收](etm-audit-2026-10-14.md)。

开发回归：`npm ci` 后执行 `npm run test:etm`（离线，不操作硬件）；完整包可执行 `python tools/dev/test-etm.py --portable --output <新证据目录>` 验证。
