# ETM 功能审查与自动化验收

本轮针对 `web-serial-rtt-tools` 的 ETM 嵌入页及完整桥包；基线 `6f51462`，原工程基线 `f12351a`。原工程的修改在 Codex 自有 worktree 完成，再同步经过审查的运行快照。未修改探针固件、目标固件、Kingst 全局设置或已有用户记录，也未推送远端。

验证证据根目录：`E:/web-etm-trace-coordination/artifacts/etm-audit/20261014-etm-audit-8c38e57e`。详细日志、失败波形、版本与 SHA256 清单保存在该目录；它们不会随 Git push 自动上传。

## 本次确认并处理的问题

| 问题 | 后果 | 修改及验证 |
|---|---|---|
| Kingst 离线 / 空 CSV 抛出 `SystemExit` | 工作线程退出，任务永久停在准备或解码 | 改为可捕获异常，工作线程兼容捕获旧退出异常；失败任务有终态 |
| 检查是否忙与创建采集任务不原子 | 两个窗口同时启动同一台 LA | 在锁内预留任务；25 对并发请求各只准入一个 |
| 重复解码同一记录 | 并发改写结果与派生索引 | 返回当前解码任务；同一记录采集未结束时拒绝解码 |
| 文件准备 / 启动线程失败后留下 queued | 后续采集一直被拒绝 | 创建失败转入 error；保留首次错误 |
| queued 阶段不能取消，停止与启动有竞争 | 停止后又发 start / CPU 继续 | 原子切换 LA 启动状态；提前取消不连接 LA；停止请求阻止继续 CPU |
| 请求、任务轮询无截止时间 | 按钮永远禁用 | API 超时、任务总期限和各阶段期限；每个测试进程有 watchdog |
| 参数错误、LA 离线在复位后才被发现 | 无效操作也改变目标状态 | 参数与 LA 支持率先检查，再核对 ELF/运行起点；无效参数用例没有目标写操作 |
| LA 断开 / 停止等待后仍导出缓存 | 可能把上次波形当成本次结果 | 只有完整 ACK 才导出；等待时停止记为取消，不保存不明缓存 |
| 停止没有确认还允许再次采集 | 新操作与旧采集竞争 | 保留待停止任务、禁用新采集，提供显式重试停止 |
| ELF 文件回调绕过父页仲裁；导入未互斥 | 其它功能可抢走探针；任务状态互相覆盖 | ELF 经父页队列；导入互斥；迟到的文件选择结果被拒绝；后台回读也纳入仲裁 |
| SWD 故障后断点恢复列表丢失 | 恢复连接后断点仍未下发 | 保留挂起断点子集；显式恢复后先核对 ELF，再恢复已验证断点。故障期间继续禁止寄存器写入 |
| 直接采集 / 原始导入假定 ETMv4 | F103 ETMv3 配置错误 | 使用明确的目标回读；断开后保留回读；更换 ELF/型号后失效；无配置时拒绝假定协议 |
| 记录切换、导航、缩放的旧响应覆盖新状态 | 源码错位、加载状态过早解除 | 按记录代次丢弃过期响应；原始记录清空旧图、指标与选中状态 |
| 按钮缩放保留 cursor，滚轮/拖选却把 cursor 改成首条 | 同一功能不同操作方式表现不同 | 复现后修复：滚轮优先以 cursor 为焦点；cursor仍在新区间时保留；超出区间才选首条 |
| 内嵌面板异常后重试直接早退 | 白屏 / 无可用恢复入口 | 显示父页错误；重试先停止并释放旧连接；忙或清理失败时不抢占、不丢弃连接 |
| JSON 文件直接改写及 Windows 文件替换竞争 | 读取半截 JSON / 瞬时拒绝访问 | 原子保存、读取配合锁、仅对替换动作作有界重试；100 次并发写、1000 次读验证 |
| 重建 SQLite 索引时旧读请求仍持有文件 | Windows 拒绝替换，分析页偶发报错 | 实测复现；有界等待旧读者关闭，始终保留旧索引；两仓均有并发回归 |
| Host 只由请求自己证明；记录 input 没有在读取时校验 | 意外访问本地服务 / 记录目录之外文件 | 仅接受回环 Host；输入文件名白名单；外域 Host、跨来源修改及路径测试 |
| 不完整记录包 / 非法寄存器 / 其它 ELF 的源码可进入后续流程 | 不可用导出、错误配置或源码错配 | 完整记录必备文件检查，32 位寄存器校验，源码 ELF 指纹校验 |
| 解码没有包含所选起点却未专门提示 | 误以为完整恢复了初始化入口 | 新增起点恢复诊断；未恢复入口时显示警告；派生索引版本升级以覆盖历史记录 |
| 原测试依赖编译机路径与 SDK 构建产物数量 | worktree 中假失败，回归不可复现 | 源码显式快照与 SERIAL_ROOT；真实 SDK 加 5000 个不会读取的无关路径 |

## 批量自动化

普通离线回归：`npm ci` 后运行 `npm run test:etm` 或 `make test-etm`。`make test` 已纳入 ETM。包含真实页面 HTML/控制器与父页仲裁；设备响应由测试模型提供，**不是硬件通过**。每个测试进程有 240 秒 watchdog，保留日志与 JSON 结果。

`python tools/dev/test-etm.py --portable --output <新的证据目录>` 额外检验完整桥包的独立启动、默认 bundle、中文空格路径、Demo 原生解码和下载。实板脚本另行运行，必须独占探针与 LA；普通测试入口不会操作硬件。

主要参数与操作矩阵：

- 200 次实际页面控制器的 ELF 优先/连接优先、验证失败、起点失败、采集、清理、恢复顺序。
- 192 种任务状态顺序，以及每个阶段卡住、请求不返回、无效响应、提前停止。
- 336 组采样率/时长/相位边界，120 种通道排列、20 种重复通道，25 对并发采集、22 组停止状态；另有 Host/路径检查。
- 1000 次缩放/fit 边界与 cursor 保持；记录切换、同记录重复加载、迟到导航与缩放响应。
- 100 次并发元数据写、1000 次读取，不出现半截 JSON；Windows 竞争失败日志也保留。

## 实板发现

F103ZE，板上 `fw-ze.elf` SHA256 `63881ed9f6c1187d56924795ccad3f151a677aea0dfa201823fe44e0cb857522`，Flash 20168 字节核对一致，CPU48/TRACECLK24 MHz，CH0..4=PE2..6。本轮没有烧录。使用生产工具箱 `WebUsbDapProbe` 经原始 USB bulk 字节转发运行控制逻辑，**没有把 pyOCD 或模拟模型当成浏览器驱动**。

500 MSa/s、相位0.25 的 11 个场景通过：1/2/5/10 ms 复位采集，运行至循环起点采集，queued/armed 取消，取消后复位再采集，一次性入口不复位的预期超时，等待入口取消，软件故障锁存后的实板调试口恢复。六个有效窗口恢复 8475/26724/81425/172601/174819/81426 条指令，overflow/包错误/未处理字节/未知源字节均为0；不能因此声称无损。结束恢复 CPU 运行并释放探针。

**起点精度不足已实测**：选中 `cdc_acm_init=0x080004d0` 并确实停到该地址，多个窗口第一条恢复指令却是 `cdc_poll` 中 `0x080005a0`，初始未同步约1017字节。应补“LA先就绪，再启用trace”的精确同步启动机制；本轮仅标明缺口，不用统计正确替代精确入口保证。

**200 MSa/s 相位敏感已实测**：原相位0.25报 OpenCSD 错误，原始波形保留。在同一波形离线扫描中，0.05/0.10/0.15/0.20及0.80/0.85/0.90/0.95均恢复26724条指令，包错误和overflow为0，产生完全相同的 ETM 字节流（SHA256前缀 `b8ed0154b124`）。其它多处相位仍失败。这不能等同于所有200M现场已认证，也未改全局默认相位；500M/0.25继续作为本例基准。

随后真实重新采集 200M/相位0.10 的 2 ms、5 ms 窗口，也通过解码与零包错误核对，并重复入口超时/取消/显式恢复；这组5个场景另有独立报告。相位窗口的差别可能受接线、信号延迟和采样量化影响，不能直接推广到其它板卡。

本轮失败日志保留，包括 Kingst 服务起初离线、200M/0.25 解码失败，以及测试脚本将“reset-after-stop”错误归类为取消的断言失败；修正该测试分类后重新完整实测通过，没有隐藏或覆写首次失败。
