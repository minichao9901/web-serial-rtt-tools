# 异常诊断与采集质量报告

这两个入口复用现有工作台，不增加独立顶层页面：

| 场景 | 入口 | 作用 |
|---|---|---|
| 调试异常 | 调试器右侧「异常」页签 | 读取停止现场、解释寄存器、恢复可验证的异常帧与源码位置 |
| 变量波形 | J-Scope 底部「质量」 | 区分探针跳拍、目标读错、USB 缓冲丢样、包缺口和网页溢出 |
| 日志接收 | RTT 转发底部「质量」 | 区分目标读取、串口连接、文本显示保护和文件写入积压 |

质量抽屉覆盖右侧区域，不挤占波形高度。关闭按钮或 Esc 可收起；切换页签时自动收起。
本轮不接入 ADC，也不改变 SPI转发页面。

## 调试器：先保留现场，再解释异常

连接目标，载入与板上固件匹配的 ELF，暂停后点「读取现场」。诊断本身不主动暂停、继续或复位目标，不清除异常标志，不初始化 DM 或修复已故障的调试口。
读失败后保留已经取得的寄存器，立即停止后续诊断、后台观察和调试器 RTT 读取；用户可判断现场后再执行下一条调试操作。
读取与普通调试操作共用独占锁，并限制读取预算与展开深度。

### Cortex-M3 / M4 / M7

- 读取 CPUID、ICSR、SHCSR、CFSR、HFSR、DFSR、MMFAR、BFAR、AFSR 和当前 PC / LR / xPSR / SP / MSP / PSP；M7 额外保留 ABFSR 原值。
- 按 CFSR / HFSR 解释 MPU 访问、精确／非精确总线错误、未定义指令、执行状态、协处理器、未对齐和除零等原因。
- 只有 MMARVALID / BFARVALID 置位，才把 MMFAR / BFAR 标为有效故障地址。其余情况下仍保存寄存器原值，并注明不能按故障地址解释。
- 只有位于故障处理上下文、栈未报告入栈／出栈错误时，才尝试恢复硬件帧。检查 EXC_RETURN、MSP / PSP、基本／浮点扩展帧、xPSR Thumb 位、返回模式、RAM 范围、对齐和 ELF 代码范围。
- 向量入口处的有效硬件帧可以直接恢复。离开入口后，先借助现有 CFI / EHABI 展开验证处理函数保存的 EXC_RETURN；仅通过结构校验的帧显示为候选，不伪装成已确认的异常前现场。
- 恢复异常前调用链使用硬件保存的寄存器。在向量第一条指令尚未执行时，r4–r11 仍是被打断的值；离开入口后，仅保留 CFI / EHABI 展开规则确认可恢复的值，不把处理函数当前的帧指针直接冒充异常前帧指针。没有展开信息、栈损坏或读取越界时停止，并显示原因。
- 基本帧和浮点扩展帧的 R0 都位于当前异常栈的起始位置；浮点扩展区增加 72 字节总长度，并不把核心帧起点后移。已用 H743 PSP 浮点异常的真实栈内容对照验证。

非精确总线错误的保存 PC 可能晚于致错指令。即使保存帧有效，也不能将源码落点宣称为准确致错位置。
异常标志具有粘性，可能来自更早的故障；诊断不会为取得“干净结果”而清除它们。
目前不套用 M3/M4/M7 语义到 Cortex-M0/M0+ 或带安全状态的其它内核。

**可选「捕获 HardFault」**默认关闭。勾选后显式设置 ARM `DEMCR.VC_HARDERR`，异常发生时内核停止；保留其它 DEMCR 位。
关闭或断开时恢复接管前的捕获位。恢复失败会在命令窗口提示可能保留捕获位，不静默报告成功。该开关不适用于 RISC-V。
普通停止刷新发现 ARM 的 IPSR 为 HardFault/MemManage/BusFault/UsageFault 时，会自动读取一次并打开「异常」页签。

### RV32 / RISC-V

读取 `dpc`、`dcsr`、`mcause`、`mepc`、`mtval`、`mstatus`、`mtvec`，区分异常和正常中断，并解释常见 trap 原因。
诊断先现场确认 hart 已停止，绕开普通寄存器读取中可能执行 halt 的辅助路径；发现目标仍在运行就退出。

机器级 CSR 保存最近一次 M 模式 trap，不保证对应当前停点，也不覆盖被委托到 S 模式的 trap。
`mtval` 含义依异常与实现而定；非法指令时可能保存指令位，零值也可能表示实现没有提供附加信息。
通用 CSR 不能代替固件的 trap 保存帧，因此本版不承诺 RISC-V 异常前完整调用链。`mepc` 可关联匹配 ELF 的源码位置，并明确标为历史 trap 位置。

### 现场时效

继续、单步、复位、写入、断开或更换 ELF 后，旧快照显示为历史记录；不会跟着新的 PC 重新贴上“当前现场”的标签。
源码按钮只查看源码，不写寄存器，也不把异常帧冒充成调试器的当前局部变量栈帧。

## J-Scope：不同阶段、不同单位

| 指标 | 单位 | 含义 |
|---|---|---|
| 探针跳拍 | 采样时刻 | 探针未赶上计划时刻 |
| USB 包缓冲丢样 | 样本 | 探针没有空闲包缓冲，或包提交失败 |
| 目标读取失败 | 次 | SWD / JTAG 读取或流水线收尾失败 |
| 给调试让路 | 次 | 探针让出调试链路；不等于丢样 |
| 包序号缺口 | 包 | 接收序号缺失，可能是 DATA、DEF 或 STAT；不能直接换算为样本 |
| 网页缓冲溢出 | 样本 | 网页存储达到容量上限，后续样本未存入波形 |
| 实测平均采样率 | Hz | 保留样本数与探针首尾时间戳计算；不是主机 USB 到达速率 |

计数不能简单相加为总丢样数。探针 `produced` 包含部分未送出的样本，USB 丢样可能与其重叠；读错还可能发生在流水线收尾。
只有完整 32 位原子快照、USB 丢样与读错均为零、且未观察到计数回卷时，才计算 `skipped / (produced + skipped)` 的跳拍率。其它情形显示未知，保留分项证据。

采集开始时冻结请求周期、时长、通道、ELF、时钟和模式设置；停止后保留本次历史报告。回放数据不引用当前探针计数。
现有包解析与轮询提供数据；质量统计不增加逐包计时或自动硬件轮询。完整快照在采集启停时取得，运行中可点「刷新计数」主动读取；停止后的按钮禁用，避免把其它采集／标定的计数混入历史报告。
超过 5 秒的运行中完整快照不作为当前证据；新 STAT 可提供部分计数，但 16 位字段会回卷，不能由此反推精确跳拍数或跳拍率。

值恒定只能说明观察到的值没变化，不能据此断言缓存有问题。应同时核对程序运行状态、变量地址、ELF 与已烧录固件、内存区域和缓存可见性。

## RTT 转发：把接收、显示、落盘分开

面板显示网页累计接收与最近 1 秒速率、探针搬运字节、目标读错与 RdOff 写错、调试让路、保留显示历史、省略渲染以及文件写入／积压。
探针状态超过 6 秒、连接已断开或状态读取失败时显示不可用；可以主动刷新已有状态接口。

- 文本显示暂停、高速保护和显示历史裁剪都不等于传输丢包。高速保护会省略显示历史，完整接收需提前开启文件记录。
- 文件积压表示尚未落盘；溢出或写入失败才是已确认的记录完整性问题。
- 文件带时间戳时，写入字节包含附加文本，不能与原始接收字节直接比较。
- 网页接收与探针搬运计数起点不同，不能直接相减算丢字节。共享串口由其它功能打开时，会注明来源不确定。
- RTT／CDC 原始字节流没有应用层序号与校验，不能计算误码率，也不能由零读错推导零误码。
- 搬运量不增长可能是目标暂停、没有日志或另一路读走日志；不会直接断言冲突。

## 导出与证据等级

三个面板均可导出 JSON 与可读 Markdown 报告，包含版本与设备信息、配置、带单位和来源的计数、判断、解释边界及最近 128 条事件。
异常报告还含原始寄存器、保存帧和展开结果。JSON 的 schema 为 `akalink-diagnostics/v1`，导出时复制快照，不随后续采集改变。

判断使用三种等级：**已确认**（计数／寄存器直接支持）、**可能原因**（可解释现象但尚未区分）、**证据不足**（缺失、过期或机制本身不能证明）。
缺失数据保持 `null`，不补零。报告不是自动修复操作；不会改目标固件或执行控制状态。

## 验证与参考

本版已验证逻辑模型与真实浏览器界面：基本／浮点帧、坏栈与有效位、读取失败后停止、RV32 异常与中断、历史状态、捕获位恢复、单位／时效／回卷、JSON/Markdown 导出，以及约 200 KiB/s、2 MiB/s 的浏览器模拟突发接收。
模型与主机交互验证不替代板上结果。另已完成 [H743 真机验收及性能对照](validation/2026-10-08-h743-diagnostics.md)：8 个真实异常场景、基本／浮点 MSP/PSP 帧、处理函数序言后的恢复、只读一致性及捕获位恢复；对照开发前标签测量正常调试、J-Scope 和 RTT。相同生效时钟下没有观察到明显吞吐下降，60 MHz 压力下的降档、数据模式不连续及 USB 丢样均单列保留。

复现：`make test-diagnostics`；启动本地服务与 CDP 浏览器后 `make test-diagnostics-page`。页面测试建立独立标签，使用模型，不烧写目标固件。

寄存器语义参考 [ST Cortex-M4 编程手册](https://www.st.com/resource/en/programming_manual/dm00046982-stm32-cortexm4-mcus-and-mpus-programming-manual-stmicroelectronics.pdf)、[ST Cortex-M7 编程手册 PM0253（图 11：异常保存帧）](https://www.st.com/resource/en/programming_manual/DM00237416.pdf)、[Arm CMSIS 核心头文件](https://github.com/ARM-software/CMSIS_5/tree/develop/CMSIS/Core/Include) 与 [RISC-V Machine-Level ISA](https://docs.riscv.org/reference/isa/priv/machine.html)。
探针计数语义依据固件 `scope_sampler.c` 和网页 `scope/protocol.js`、`hid/probe.js`，不套用缺乏证据的吞吐模型。
