# RTT 转发突发流量导致页面无响应：显示路径取证

日期：2026-10-07。用户在 HPM6800EVK `lwip_tcpecho` 上执行 `make tcpecho` 后触发大量 trace，Chrome 报页面无响应。截图显示 CDC 接收总量 15.28 MB、25794 段，速率约 538.9 KB/s，显示缓冲 2 MB；RTT 转发读错与 RdOff 错均为 0。截图中的高流量提示并不代表所有显示消费者都停止工作。

## 已复现的主要瓶颈

`app/core/rxview.js` 的 `setDisplayOff(false)` 会调用同步 `repaint()`。`repaint()` 遍历全部 raw 历史，每段调用 `_append()`；默认自动滚动时，每个 `_append()` 又读取 `scrollHeight` 并写 `scrollTop`。前面刚修改 DOM，下一次读取尺寸即触发布局。接收缓冲达到 2 MB 时，会在一个同步调用中反复执行大量布局。

触发条件包括高流量回落后自动恢复显示、手动恢复显示、暂停后继续以及切换显示模式。高流量门控每 500 ms 检查一次，RTT 与串口助手各有独立门控。因而“高流量期间关显示”不能消除随后恢复历史时的阻塞。

在同一 Chrome 的独立测试页面加载真实 `index.html` 和真实 `RxBuffer`，RTT 转发为当前活动标签。使用带换行的 trace 文本，默认 ASCII、4000 行显示上限、2 MB raw 上限，直接填充历史后调用原 `setDisplayOff(false)`，通过浏览器 `Performance.getMetrics` 统计布局。对照实验只临时拦截 `_scroll()`，将尺寸读取和滚动移至整次重建结束；没有修改生产源码。

| 场景 | raw 字节 | 同步耗时 | 布局次数 | 布局耗时 |
| --- | ---: | ---: | ---: | ---: |
| 原代码，128 段 | 134400 | 1077.4 ms | 129 | 1014.3 ms |
| 原代码，512 段 | 537600 | 9533.2 ms | 512 | 9153.9 ms |
| 同样 512 段，仅最后滚动一次 | 537600 | 55.5 ms | 1 | 49.7 ms |
| 2 MB 历史，仅最后滚动一次 | 2096850 | 60.9 ms | 1 | 30.4 ms |

约 525 KB 历史已足以阻塞主线程 9.5 秒，足以解释页面无响应。2 MB 对照验证只对合并滚动的版本执行，未让用户原页面再次承受同步重建。不能把 9.5 秒当成用户原现场精确测得的卡顿时长。

## 隐藏页面仍在工作

`app/main.js` 中串口助手、终端与 RTT 转发共用同一个 `SerialSession`。三个对象都监听同一 `data` 事件：

- `app/hid/stream.js`：接收计数、记录、RxBuffer，以及可选 ANSI 解析。
- `app/serial/assistant.js`：隐藏时仍接收 RxBuffer / 可选 ANSI，同样拥有自己的高流量恢复重建路径。
- `app/serial/terminal.js`：无活动标签判断、无高流量门控，始终执行 `_feed()` 和 `term.write()`，做换行转换及 xterm 解析排队。

在 RTT 活动标签中，通过真实 `SerialSession.emit('data', ...)`，临时统计三个处理器，确认一次事件分别触发 1 次隐藏终端写、1 次隐藏串口助手 push、1 次 RTT push。计数测试后立即恢复原方法。该结果确认隐藏消费者确实存在，但尚未量化 xterm 在用户现场总阻塞中的占比。

## 当前限制与后续修复范围

用户原页面已无响应，向该页面发送 `Debugger.enable` 在 6 秒内未得到响应，未获得当时的原始调用栈。保留原页面，不刷新、不关闭，以避免丢失用户 ELF、源文件句柄、波形和未保存记录。本轮未重启硬件、未停止用户目标，也未重新打 TCP 流量；确定原因来自独立页面的可重复显示实验，而非宣称捕获到了原页面的现场栈。

建议修复：历史重建合并 DOM 更新、整批只滚动一次；显示输出按时间/字节预算处理，并限制恢复时一次回放量；隐藏显示消费者停止持续解析、保留有界历史与独立记录；在突发接收路径及时限速显示，避免只依赖可能被阻塞的 500 ms 门控定时器。接收统计和文件记录应继续独立工作，不能用关闭串口接收来掩盖显示瓶颈。

本次仅诊断，没有修改生产代码。实验脚本与详细结果：`tmp/rtt-render-perf.mjs`、`tmp/rtt-render-perf.json`（tmp 不纳入 Git）。独立测试页结束后关闭，用户原页面保留。

## 后续修复与验收

用户确认修复后，已实现：

- RxBuffer 历史重绘合并为一个文本节点并只滚动一次。回放最近约 128 KB，显示总量限制 256 KB 字符 / 4000 行；保留的 raw 与保存数据独立，最多 2 MB / 8192 段。过期 raw 用头游标裁剪，立即释放字节引用，避免每个小包都移动大数组。隐藏窗口不解码、不修改 DOM，切回来回放有界历史。
- 新增共用 `AnsiDisplay`：后台只保留最多 64 KB / 1024 段待显示数据；可见时每批最多 16 KB / 128 段，等待 xterm 完成回调后才交下一批。后台终端不再持续解析。显示超额有省略提示；清空同时覆盖已在解析的旧批次。
- RTT 和串口助手在接收路径检测 100 ms 突发窗口，不再只依赖 500 ms 的统计定时器关闭高流量显示。
- SerialSession 连续读取每约 8 ms 让出一个浏览器任务，而非等待 8 ms；结束流同样让步，防止 readable 更新尚未发布时空转微任务。这保留原 4096 字节串口缓冲配置。
- 文件记录与计数继续在显示处理之前执行；显示抑制、裁剪与隐藏均不截断文件记录。
