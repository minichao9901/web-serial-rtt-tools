# H743 SPI 转发启动时序与小包速率统计修复

2026-10-08，检查用户保留的实际网页和在线 H743，未烧录、未复位目标或探针。记录见 [现场 JSON](2026-10-08-spi-cdc-startup-results.json)。

## 无数据的现场

探针 SPI 转发状态为运行正常，但 received / forwarded 均为 0。H743 正常运行，g_run=1、g_mhz=10、g_spi_hz=10000000、g_core_hz=400000000，DMA 计数持续增长；PA4 的 ODR 为 0，即连续发送期间 CS 已拉低。发送端 g_clock_err / g_dma_errors 为 0，历史暂停后 g_refill_late=3。

先对运行中的 H743 写 g_run=0，确认 GPIO ODR 的 PA4 位为 1；停止并重启探针 SPI 接收；最后写 g_run=1。约 2.5 秒后探针已接收 3,144,632 B，丢弃、FIFO 溢出和 DMA 错误均为 0。该连续流夹具需要接收端先就绪，再建立 CS 下降沿；仅重启网页接收不能使已经拉低的外部 CS 重新产生下降沿。

网页补充启动顺序提示，发送夹具 README 补充手动控制方法。调试内存写入可在目标运行时执行，保持 CPU 补充 DMA 半区；启动过程可以同时连接调试器和 SPI 转发，二者引脚独立。

## 速率被低估

旧 Counter 按接收事件存储最近一秒，但超过 4096 个事件便截去 1024 个。在 10 MHz 的大量小块事件下，窗口常只剩约 0.15 秒，仍按一秒速率显示。本次四秒字节差分为 1,255,448 B/s，而旧瞬时统计只有 197,807 B/s。总字节计数没有被截去，不能把低显示值当作实际传输速率。

改为按 1 ms 聚合字节、按时间过期，使用头索引避免逐项 shift，保留每次接收事件的总帧计数。内存数量不再随同一秒的小块数量增长；滑动窗口边界有不足 1 ms 的聚合误差。本次在当前页面更新计数器方法，保留总计数与所有连接；源码修改在重新加载页面后正常生效。

## 真机确认

单通道原始 SPI/CDC，Mode 0、MSB first，探针固定模块时钟 240 MHz。每档先预热 1.2 秒，再测约 5 秒。临时校验监听器已移除，H743 最终保持 60 MHz 发送、网页接收继续运行。

稳定窗口探针 dropped / fifoOverflows / dmaErrors 增量均为 0；60 MHz 发送端 g_clock_err、g_dma_errors、g_refill_late 均为 0。监听器首次加入和速率切换期间的帧对齐、序号归零另有累计值，不能把稳定窗口零错误当作从启停开始全流程无损。该短测仅确认本次现场恢复与计数修复，不替代长时间误码验收。
