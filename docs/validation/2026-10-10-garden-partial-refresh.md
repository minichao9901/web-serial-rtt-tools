# 花园 MP4 局部刷新收益分析

用户反馈 `samples/anim/花园.mp4` 开关局部刷新后帧率差别不大。此次用同一素材、真实 Chrome 视频解码及页面实际发送路径复测；接收端是模拟探针，不代表实体探针吞吐。

## 素材与结果

素材为 H.264 视频，568×320、30 fps、11.3 秒。测试屏为 ST77916，360×360，铺满裁剪，RGB565，高字节在前，16 KiB 攒批。

| 局部刷新 | 视频样本帧 | 播放统计 fps | 每帧像素字节 | 局部帧 / 跳过 | 像素节省 |
|---|---:|---:|---:|---:|---:|
| 关 | 338 | 28.80 | 259200 | 0 / 0 | 0% |
| 开（容差 1） | 338 | 29.17 | 259200 | 0 / 0 | 0% |

两次均发送 87,609,600 像素字节，无协议错误和页面未捕获异常。少量 fps 差异来自浏览器视频呈现与计时，传输始终是同样的整屏像素量，不能解释成局部刷新提速。该页面 MP4 按媒体时间播放，正常速度不会主动超过源视频 30 fps。[原始对照记录](data/2026-10-10-garden-partial-refresh.json)。

对第一轮相邻帧再用页面同一 `diffRect` 与 `PartialRefresh` 决策逻辑统计：

| 丢弃颜色低位的容差 | 平均变化像素比例 | 平均变化包围盒面积 | 整帧 / 局部 / 跳过 |
|---|---:|---:|---:|
| 0 | 88.50% | 100% | 338 / 0 / 0 |
| 1 | 81.25% | 100% | 338 / 0 / 0 |
| 2 | 70.60% | 100% | 338 / 0 / 0 |

当前算法输出所有变化像素的**一个包围矩形**，并非逐个只发送发生变化的像素。花草摆动、镜头变化及压缩后的细节变化分布在画面四周；即使部分像素没变，包围盒也覆盖整屏。超过 60% 面积阈值便整帧发送，因此这段视频没有局部刷新收益。

## 历史提速数据的适用范围

历史真机测试使用 `ball-grid-240x296.gif`（静止网格背景与局部运动小球），开关局部刷新各播放同样时长，对比帧数、像素字节、协议帧计数及错误；另有 8×8 局部修改与整帧像素的逐字节对账。记录见 [2026-10-02 审查报告](../review-2026-10-02.md)：AXS15352 28.9 → 53.6 fps，ST77916 23.1 → 131.0 fps，均为该类 GIF 素材的结果。GIF 通路按发送速度播放，与按媒体时间播放的 MP4 不能直接比较 fps 上限。

局部刷新适合小球、指针、数字、图表等静止背景上的局部变化；不保证任意视频都会加速。界面现会显示局部帧、整帧、跳过帧和像素节省，即使收益为零也明确显示；长状态行可悬停查看完整内容。

## 预览修正

去除右上角小预览，保留不可见 `<video>` 用于浏览器解码。视频/动图加载后读取首帧，直接显示在主预览，同时更新文件名；加载过程协议发送为 0。首帧静态预览使用完整屏幕窗口，图片与图案保留原窗口行为。视频播放仍通过逐帧回调在大预览显示实际发送画面。

验证：源码版与发布版页面回归各 184 项通过，图像与协议纯逻辑测试 156 项通过。以上本轮验证未操作实体探针与屏。
