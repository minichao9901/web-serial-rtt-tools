# JScope / HSS 公式修订与 F103CB 实测优化（2026-10-07）

本轮已经修改网页和探针、真实烧录验证。推荐值是稳定采集的起点，不能把单次读取吞吐上限解释成保证无损的采样率。

## 最终结果与边界

同一 STM32F103CB，额定 72 MHz，SWD 选择 60 MHz、CDC 暂停、单字短批次开启、绘图开启、关闭原始包记录。采 `g_pack.u_hi`，地址 `0x20001028`，32 位对齐。每段预热 0.5 s，按 action 11 的 24 MHz 计时器计算正式窗口，所有正式窗口均确认还在采集。

| 项目 | 修改前 | 最终版 |
| --- | --- | --- |
| 2 µs / 名义 500 kHz：调度跳拍 | 1.6006% | 两次 0.8300%、0.8036% |
| 同档实得速率 | 491.997 kHz | 495.850、495.982 kHz |
| 2.25 µs / 444.4 kHz | 0.1130%～0.1249%（多次基线） | 0.1132%；保留原有调度节奏 |
| 2.5 µs / 400 kHz | 约 0.005%～0.008% | 0.0077%；保留原有调度节奏 |
| 每 500 ms 阻塞网页 15 ms，8 s 窗口 | 3×4096 B 预读：USB 丢样 64974 | 6×8192 B 预读：USB 丢样 0 |
| 同一配对卡顿测试总丢拍比例 | 2.3920% | 0.7987% |

配对卡顿测试使用同一最终探针固件，只改变网页预读。最终 6 段共检查 24,334,628 个值，固定高位契约异常、读取错误、序号乱序均为 0。后续另检查 4,846,788 个值的完整固定高 16 位和低 16 位计数器，异常值、计数器倒退均为 0，最大相邻增量为 1；结果见 JSON 的 `web-final-values.json`。值检查包含预热与收尾，速率和丢拍对比只采用正式窗口；不能把正式窗口 USB=0 理解为启动/停止过程也必然无丢样。

500 kHz 仍有跳拍。前期不同批次策略/启动相位下曾出现约 0.85%～1.60% 的波动，不能只拿某个最好数字承诺永久稳定。单通道契约检查不能证明多字段原子快照，也不代表所有变量布局都达到上述速率。多跨度、数组元素分散地址、目标总线等待都会改变成本。RISC-V 本轮只有代码/模型测试，没有重新测 RISC-V 硬件。

## 瓶颈在哪里

1. **常态最高速率的剩余损失主要在探针调度/包提交与 USB 服务路径。** M0 读取约 1.469 µs；正常实采 USB 丢样和读取错误均为零，但仍有调度跳拍。早期绘图开/关的速率几乎一样，只采不传可接近 500 kHz。单包 124 个 u32，包尾仍需正确收回 posted read 后才能交给 DMA；这些额外工作不能由 M0 的倒数覆盖。未做中断级示波追踪，不能把剩余开销全部归到某个具体 USB 函数。
2. **网页短暂停顿会耗尽预读覆盖时间，进而让探针没有空闲包。** 单字 500 kHz 的 DATA 约 2.06 MB/s，原生 12 KiB 预读只覆盖约 6 ms；探针缓冲只有 4 KiB。增加到 48 KiB 可覆盖约 24 ms，在本次 15 ms 注入场景中消除了 USB 丢样。更长停顿仍可能丢，不是无限缓存。
3. **异步完成顺序也会制造时间轴异常。** 多条 WebUSB 请求仍并发，但由一个消费者按提交顺序交付，避免后完成的前置请求被其他回调越过。重复/乱序包会明确终止采集，不能让错误回绕解释成几千秒的时间跳变。

## 实际保留的修改

- 探针仅在 SWD 单字、2 µs 档、FAST_BATCH 开启时，最多连续 64 拍并跨包边界继续。其他 <=3 µs 档仍最多 16 拍、包边界返回；更慢、多跨度、JTAG 保持逐拍调度。批次名义上限 128 µs，中断继续使能，停止/复位/控制请求、读错、无缓冲仍有界退出。
- 网页预计 DATA 流量 >=1 MB/s 时采用 6×8192 B 预读，其他情况保持 3×4096 B；显式传入的自定义传输配置不被覆盖。队列有界，完成结果保持提交顺序，停止/重启仍追踪所有原生请求。
- M0 改用独立、对齐的 64 B 缓冲。运行中标定在初始化前拒绝；停止后即使 USB 包池仍满，也不会把标定写进已排队的数据。退出前清空 posted-read 目的指针。真实停止后标定已成功验证。
- 新网页读取 action 11 原子 u32 完整计数，将跳拍、USB 丢样、读取错误、DAP 让路分别显示。旧紧凑 STAT/STATUS 的 16 位字段会截断，不能用于高频长窗口的准确归因；序号无缺口也不等于没有跳拍。

把采样热路径、USB 驱动移入 ILM 的实验没有明显收益，已全部撤回。32/64 拍扩大到所有 <=3 µs 档的试验在不同周期下收益不一致，最终只保留 2 µs 档的扩大策略。

## 公式修订

设成功标定的每样本读取耗时为 M0，单位 µs：

- SWD 推荐：`max(3, ceil(M0 × 1.15 + 1))`。
- RISC-V/JTAG 推荐：`max(3, ceil(M0 × 1.5))`。
- 只接受完成计数正确、err=0 的成功标定。失败时不修改周期；地址/类型、ELF、连接、后端、模式、选择和实际时钟变化都会使旧标定失效，标定过程中改条件也会拒绝结果。
- 所有模型按实际对齐读量、合并间隙计算；SWD 还计算 1 KiB 自增页拆分和时钟。保持选择不变时，探针实际降档优先于选择值。
- SWD 稳态块读为 N+2 次传输。60 MHz 的经验成本 `3.35 + 0.279 × 实读字节数` 含软件开销，不能把固定项误写成 3 次线上传输。时钟调整保留软件固定成本、只缩放传输部分。
- 当前 JTAG 块读粗估按每 span 的 N+4 次稳态 DMI 扫描；冷配置和重试另计。单字采用历史锚点，实际计划成功标定优先。
- 删除未经证实的 1.75 MB/s 硬上限。线上 DATA 流量按 `512 / floor(496 / 帧字节数) × 名义采样率` 算，状态包另计。

本板实际 M0 1.469 µs，因此建议起点 3 µs。它比追求 500 kHz 的 2 µs 档保守，这是给调度和传输留余量。目标主频与实际 SWD 降档都会改变标定结果。
