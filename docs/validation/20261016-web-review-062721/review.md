## 2. 功能问题（按优先级）

### F04 · P1：SPI 忙碌期仍允许修改配置、切档及复位桥

**位置**：`app/spi/bus-view.js:384–391`、`:558–595`；`app/spi/panel-view.js:584–594`；`app/spi/session.js:307`、`:337`、`:373–387`。

**触发**：同一个 SPI 会话正在发送命令、刷图、初始化或擦写外部 Flash，用户切到总线／屏配置／状态，再点击写入配置、应用引脚、切换档位、失能、复位或底层中止。

**证据**：实际 `SpiBusView.refreshButtons()` 在 `connected=true, busy=true` 时，`sp-set`、`sp-pin-apply`、`sp-disable`、`sp-reset`、`sp-abort` 均保持可用；实际 `SpiSession.reset()` 仍发送 RESET，没有会话级忙碌检查。屏页的 `pn-prof-set`、`pn-enable`、`pn-disable` 同样只检查连接状态。`wrap()` 只处理错误，不做互斥。

**影响**：页面的任务互斥只挡住另一项数据任务，未挡住会改变同一任务硬件环境的控制命令。对照固件 `spi_bridge.c:2267` 与 `:2370`，在普通 bulk 任务期间 SET_CFG／SET_PROFILE 会请求硬件重初始化；RESET 会登记清环请求。周期引擎的固件忙碌检查可以挡住部分命令，不能覆盖全部普通 bulk 任务。本轮确认的是控制命令可穿透忙碌期，未进行实板破坏性验证。

**补充证据**：模拟切换也没有忙碌检查：`setMock()` 直接 teardown，两个页面的模拟复选框仍可操作；故障脚本 F04b 确认 busy 时仍进入 teardown。

**建议**：在 `SpiSession` 统一区分只读状态查询、改变配置的操作、任务专用停止／恢复操作。忙碌期拒绝无关配置写入，两个视图据此更新按钮。保留任务专用中止能力，不能把全部按钮简单统一禁用。

**验收**：分别在命令发送、屏初始化、刷图、Flash 任务期间跨两页操作；配置不能改变当前任务。只读状态和该任务允许的停止保持可用。

### F05 · P2：SPI 周期任务 STOP 失败后，常规停止／断开缺少恢复入口

**位置**：`app/core/bus-periodic.js:146–156`；`app/spi/runner.js:105`；`app/spi/acq-view.js:58–60`、`:119`；`app/spi/session.js:232–233`；`app/core/probe-users.js:59`。

**触发**：真实周期采集退出时，STOP 的传输／确认失败。

**证据链**：周期会话保留 `stopError`、`owned` 并维持 `busy=true`；Runner 随后停止，`running=false`；视图因而禁用“停止”。“关闭探针”也因 busy 被禁用，即使直接调用 `disconnect()` 仍返回 false。另一项使用共享资源的 I2C 操作又会被 SPI 的 busy 保护拒绝。底层确有 `stopSessionPeriodic()` 的重试分支，但常规停止／断开动作没有可到达的恢复入口。勾选“用假探针”会意外通过 setMock → teardown 触发重试，这是一个隐藏绕行，不能据此声称页面绝对无法恢复，也不适合作为实际采集错误的恢复交互。实际类故障状态复现中同时出现“停止禁用”“disconnect=false”“I2C 接管被拒绝”。RTT 与 SPI 不共享这些资源，不应拿 RTT 接管作为此问题的复现条件。

**影响**：一次可重试的停止错误，会使正常操作流程卡在忙碌状态，需要用户知道切换模拟探针的隐藏绕行。保留占用本身是正确保护；缺陷是缺少清楚、针对当前真实会话的恢复动作。

**建议**：将 `running / stopping / stop-failed` 显式区分；STOP 未确认时显示“重试停止”，调用既有 `session.stopPeriodic()` 并保留资源，成功后再允许断开或接管。需要同时覆盖断开按钮和全局资源提示。

**验收**：故障注入让第一次 STOP 失败、第二次成功；不刷新页面、不拔插、不手动执行控制台代码，也能完成恢复，且恢复前不能让冲突功能启动。

### F06 · P2：SPI 失能未生效仍返回成功并打印绿色日志

**位置**：`app/spi/session.js:373–379`。

**触发**：ENABLE(false) 返回的状态仍是 enabled，例如周期引擎占用时固件拒绝该操作。

**证据**：`setEnabled()` 只对 `on && !st.enabled` 做失败处理；`on=false` 时无论返回的 enabled 是什么，都记录“桥已失能（引脚恢复默认）”并返回 true。向实际方法注入“仍 enabled”的应答已复现。固件 `spi_bridge.c:2228` 的周期占用分支确会返回仍 enabled 的状态字。

**影响**：用户可能据此误以为引脚已经释放；之后重新读状态也不能使此前的成功日志成立。

**建议**：以读回的 enabled 状态和必要的有限等待确认使能／失能结果，失败明确返回或抛错。不要因为状态字里存在历史 err 就一概判失败：该错误字段具有粘性，必须区分状态确认与历史错误。

### F03 · P2：ADC 新采集启动失败会先删除上一份波形

**位置**：`app/analog/view.js:92–100`；`app/analog/session.js:59–63`。

**触发**：已有历史数据，随后在未连接、采样率／位宽／长度无效或启动条件不满足时点击单次／运行。

**证据**：View 先 `store.reset()`、清 total 和 lastFrame，才调用会检查连接与参数的 Session。实际类复现：原有 3 个样本，启动返回“先连接探针”，历史长度已变为 0。

**影响**：一次没有成功开始的新任务，也会使原波形无法查看和导出。

**建议**：先完成参数和连接前置检查；最好在新采集已被接受／首个有效数据块到来时再切换数据仓。启动异常保留上一份结果，并标明新任务未开始。

### F01 · P2：串口写失败被转换为成功 Promise

**位置**：`app/serial/session.js:190–209`；`app/serial/assistant.js:296–302`。

**触发**：串口底层 `writer.write()` 失败，或者队列中的写操作发现会话已切换。

**证据**：内部 `_wq.catch()` 发出 error 后吞掉异常，返回给调用方的也是被吞掉的 Promise。注入写失败后，error 事件正常发出，但 `await session.write()` 不会拒绝，Assistant 的 send 仍可返回 true。

**影响**：页面错误提示仍可通过 error 事件显示，因此不是“所有错误都静默消失”；问题是调用者无法据返回值判断本次是否发送成功，发送编排和后续动作会得到错误结果。

**建议**：保留两个 Promise：本次操作返回原始 task；仅内部串行链使用 task.catch() 恢复，以允许下一次写继续。调用点必须处理本次 task 的失败，不能为修复错误传播而把整条链永久留在 rejected 状态。

### F02 · P2：定时发送没有背压，停止定时后仍可能继续发送积压命令

**位置**：`app/serial/assistant.js:306–311`；`app/serial/session.js:202–209`。

**触发**：定时周期短于串口一次写入实际完成时间，或者设备暂时阻塞写入。

**证据**：`setInterval()` 不等待 send 完成，每拍把新写入排到无界 Promise 链。复现中停止定时时已提交 5 次写入、完成 0 次；放行底层写入后，5 次积压全部继续发出。清掉定时器只阻止未来提交，不会取消已排队的定时发送。

**影响**：停掉定时复选框后还有旧命令持续发出；长时间阻塞还会积累内存与等待时间。

**建议**：定时发送最多允许一笔在飞；明确“上一笔未完成则跳过／延后”的策略。用定时任务的代次或取消令牌让尚未提交到底层的旧定时写失效；已经进入底层的一笔按实际结果完成。普通人工发送不应随定时任务取消。

### F07 · P2：烧录器漏接 onShow，跨页更换 HPM 板后保留旧选择

**位置**：`app/main.js:92–109`；`app/flash/view.js:143–146`；`app/targets/hpm/select.js:11–19`。

**触发**：烧录页选择 HPM5301EVKLite，在调试器选择 HPM6800EVK，再回烧录器。

**证据**：主页面切换分发中缺少 `flash.onShow()`。该方法本来负责在无任务时同步全局 HPM 板型。浏览器实测返回烧录器后，调试器为 `hpm6800evk`，烧录器仍为 `hpm5301evklite`，见 [JSON](flash-target-sync.json) 与 [截图](flash-target-sync.png)。

**影响**：相邻页面的当前目标不一致，烧录前选择可能落后于全局板型。现有身份校验仍是必要保护；本轮没有证明它会绕过身份校验写坏另一型号芯片。

**建议**：补上 onShow 分发，并用统一页面登记表派生切换回调，避免 15 个手写 if 再次漏页。通过模型层同步当前目标；有任务时不应偷偷切换板型。

## 3. 过度防御、冗余与合理保护

### 应保留的保护

| 设计 | 审查判断 |
| --- | --- |
| ProbeManager、跨标签 ProbeBus、USB 接口租约三层 | 分别处理业务资源、同源多标签协调、真实 USB 句柄／接口所有权，职责不同，不宜合并成一个 busy 布尔值。相关回归已执行。 |
| STOP 未确认时保留占用、关闭失败保留句柄 | 有必要。F05 应补恢复入口，不能靠清空 busy／forget 伪装释放。 |
| 操作代次、启动／停止 Promise、AbortController | 分别覆盖排队取消、在飞收尾、迟到回调；不能只因字段多就删掉。 |
| SPI/I2C 真实周期在探针上执行，假设备使用浏览器定时 | 保持。真实采样时间不能以页面收到数据的时刻替代。C/JS 协议、停止重试、满队列停采已在补齐环境后验证。 |
| 固件／ELF／协议长度和读取范围校验 | 属于外部输入及硬件边界，不能归为过度防御。 |
| 高流量时停显示、继续采集／记录，缓冲有界 | 合理，显示与采集应继续分离。不能通过放开所有渲染来解决“页面看不到数据”。 |
| SWO/ETM 的现场恢复、临时断点回读和镜像核对 | 风险与动作相称；本次 ETM 恢复／操作顺序回归通过，不沿用旧报告已经修复的结论。 |

### 可以精简的部分

1. **页面与 onShow 登记重复**：HTML 已是一份页面清单，main.js 又维护一长串回调；F07 已说明这种重复会造成遗漏。建议一个简单登记表，不需要引入前端框架。
2. **工作区 Tab 逻辑复制**：调试器、SPI、屏、I2C、工程生成各自重复维护 class、持久化、面板显示。已有 `sidebar-tabs.js` 可作接口参考；抽一个纯布局的通用 Tab 控件，统一键盘与 aria，不把设备操作塞进去。
3. **CSS 以追加覆盖方式累积**：`app.css:52` 与 `:1235` 等位置重复定义顶栏，前后的响应式规则还有不同的 flex-wrap 设定。390 像素宽时顶栏超出 15 像素。建议先收敛顶栏／工作区布局的唯一规则，再逐个清理覆盖层；不建议全局机械合并选择器。
4. **共享 SPI 状态在两个视图各自推导按钮**：F04 表明规则已漂移。用一个会话能力查询统一可读、可改、可停止、可恢复，再让视图显示状态；避免再增加第三套 UI busy 状态。
5. **旧注释和流程说明滞后**：`main.js` 仍写“三个标签页”，`hid/view.js` 仍描述面板挂在终端。将历史事故长段说明浓缩为约束与测试入口，保留必要背景，降低维护时理解成本。
6. **隐藏页面仍刷部分统计／实时值**：串口与多个流视图的固定统计定时器、SPI/I2C 实时值重建可统一采用 dirty + 可见性策略，切回页面补绘。当前只有结构证据，没有 CPU 对照测量；列为优化候选，不作为已确认性能故障。
7. **资源声明偏保守**：SPI 总是占用 I2C 引脚资源，代码已有配置感知租约的 TODO。这会限制某些实际上独立的组合，但与辅助脚可复用有关。只有明确引脚配置和硬件并行验收后才宜缩小范围，不能直接删互斥。

## 4. 全页面／每个 Tab 的界面建议

共同基调建议保留当前深色工程工作台，优先改信息层级和操作可理解性。无需添加装饰性大卡片、渐变和动效。13px 默认字重与大量 12px 提示适合密集数据，但主操作、连接状态和当前任务可略放大；技术元数据保持紧凑。

### 4.1 串口助手

- 已检查：接收 ASCII／ANSI／HEX；发送 ASCII／HEX。
- 功能：共用 SerialSession 的思路正确；处理 F01、F02。时间戳、暂停显示和文件记录的含义应保持区分。
- **ASCII**：空白接收区可用“选择端口 → 连接 → 接收”的简短引导，并提供直达选择按钮。
- **ANSI**：在模式附近说明“终端解释转义码”；保留暂停和恢复入口。状态颜色不要把正常的“高速保护”一概显示成设备错误。
- **HEX**：保留等宽、地址／字节分组；发送区的 ASCII／HEX 与接收区模式要用“接收格式／发送格式”短标签区分。
- 视觉：参数侧栏大量同样大小的输入可把数据位／停止位／校验折叠到高级设置，保留端口、波特率和连接。快捷发送可在有内容时显示槽位，已有“添加”模式合理。

### 4.2 终端

- 已检查：回显、回车／退格映射、换行、字体与初始终端画面。
- 功能：连接与串口助手共享合理；F01、F02 的修复应回归终端输入。
- 视觉：当前大块空终端本身合理；未连接时在终端上方放一条显眼的“去连接串口”入口，避免用户必须从侧栏说明推断。把“回显／回车／退格／换行”收为清晰的终端设置组，默认以快捷方式连接页跳转。

### 4.3 RTT Viewer

- 已检查：终端(ANSI)／文本／HEX 三种显示。
- 功能：三种后端确有不同能力，不宜为简洁直接删除。识别控制块、手工地址、扫描、ELF 的入口可明确优先顺序。
- **终端(ANSI)**：适合默认阅读；把“定位并开始”放在连接后的下一步骤。
- **文本**：时间戳与日志保存优先；突出显示暂停不等于停止轮询。
- **HEX**：突出下行通道及输入格式，避免把通道选择和显示格式混在一起。
- 视觉：未连接空态建议展示两步操作，不把全部硬件差异说明塞在左栏常驻段落中；支持情况保留在后端选项旁和帮助中。

### 4.4 RTT 转发

- 已检查：ASCII／ANSI／HEX 接收模式；探针控制与 CDC 接收两段界面。
- 功能：HID 配置和 CDC 接收是两条连接，不能用一个笼统“已连接”掩盖。停止转发后复用 UART 是有效设计。
- 视觉：给两个区域显式编号：“1 探针转发”“2 CDC 接收”，各有独立状态；增加组合状态“转发已运行／接收口未打开”。波特率不作用于 RTT 内容的说明靠近参数，避免只靠长提示。
- 三种显示模式遵循串口页相同排布和按钮术语，保留显示保护与记录状态。

### 4.5 J-Scope

- 已检查：侧栏采集／变量／触发／帮助，叠加／分道显示。
- **采集**：把“探针已连、数据端点已连、变量已选”列为三个简短就绪标记；开始采样按钮固定在底部的设计可保留。
- **变量**：空态直接提供载入 ELF／模拟变量入口；变量选择计数和最多 8 项限制靠近列表，减少查帮助。
- **触发**：阈值、预触发、查找结果应分组；没有波形时标明触发作用条件。
- **帮助**：按连接、变量、采样质量分段，保留可搜索或可定位的小标题，不再嵌套过多无差别“使用说明”。
- **叠加／分道**：模式选中状态清晰；通道色应同时出现在变量列表、图例和曲线，不能只靠曲线本身辨别。
- 视觉：底部质量指标太密，建议保留采样率、样本数、丢样／错误三项常驻，其余进详情；不隐藏原始计数。

### 4.6 烧录器

- 已检查：烧录／SRAM 读写测试。
- **烧录**：修复 F07；文件选择后空白主区应优先显示文件名、格式、目标地址、有效载荷、所选芯片和将执行的步骤。现有日志区保留为执行详情。
- **SRAM 读写测试**：与烧录共享连接设置合理；把“覆盖所选 RAM”的提示保持在操作附近。结果建议用逐轮读写／校验／实际时钟表格，失败行保留原因，不只看总吞吐。
- 视觉：两个 Tab 顶部共用的目标、后端、时钟保留一致位置；主按钮文案明确区分“烧录”和“开始 RAM 测试”。

### 4.7 调试器

- 已检查：侧栏会话／断点／栈帧；工作区寄存器／内存／变量／SVD／RTT／异常。
- **会话**：当前连接与 ELF 信息可用小型摘要，避免左栏反复显示“未连接”。
- **断点**：区分已添加、待连接后安装、已命中；计数徽标保留。
- **栈帧**：明确“未回溯／无有效栈／已回溯”的不同空态，避免都写成空。
- **寄存器**：保持等宽和变化高亮；编辑与提交状态应明显。
- **内存**：地址、长度和读取动作放同一工具条；读失败保留上一块数据但清楚标注过期。
- **变量**：保留树形展开和类型；空态提供“载入 ELF／添加表达式”。
- **SVD**：型号／外设／寄存器形成稳定层级；自动读取条件和副作用说明要贴近开关。
- **RTT**：与独立 RTT Viewer 的入口差异写清楚；不要给人“两边可同时读同一个环”的暗示。
- **异常**：只读诊断定位清楚，保留捕获位恢复；诊断报告入口可归在同一动作组。
- 视觉：1440 下分栏可用，1024 下自动上下布局也可用。源码与命令行之间有大空白时可依据实际内容调整默认比例；已有最大化和收起侧栏能力应保留。

### 4.8 USB→SPI/QSPI

- 已检查：侧栏连接／总线／状态／帮助；工作区命令表／寄存器／脚本／实时值／Flash 测试／回环自检。
- **连接**：显示 HID 和数据端点分别是否完成，减少三步连接的不确定性。
- **总线**：先处理 F04；时钟、模式、CS 与辅助脚分为基础／高级两组，区分编辑值和实际读回值。
- **状态**：保留读取、复位桥、底层中止的不同语义；依据 F04 禁止任务期间任意改变状态。
- **帮助**：按接线／协议／周期任务分段，术语与界面按钮一致。
- **命令表**：字段列标题增加紧凑提示；空行的输入格式清楚，结果使用文字加颜色。
- **寄存器**：读、改、提交、回读差异集中在表附近，避免用户在日志里找是否生效。
- **脚本**：语法错误、解析预览、运行／停止形成连续步骤。F05 的“重试停止”必须在这里及全局运行摘要可见。
- **实时值**：空态给一个“载入带 as 的示例”入口；变量卡或表格保留单位、样本数、实际频率，迷你曲线作为辅助。
- **Flash 测试**：读操作与擦／写操作视觉分区；原有写入确认是针对外部 Flash 的必要保护，不应因“过度防御”删掉。
- **回环自检**：先说明接线，再给运行入口；结果表突出失败轮次、字节差异和实际配置。

### 4.9 SPI/QSPI 屏

- 已检查：侧栏连接／屏配置／控制／帮助；刷屏／面板初始化／读回。
- **连接**：与 SPI 桥共享一次连接合理；两页都显示“共享 SPI 会话”，并能直达对方的高级配置。
- **屏配置**：区分屏型号推荐值、待应用参数、固件已生效值；先修复 F04 的切档穿透。
- **控制**：背光、休眠／显示、复位应分组；十六进制命令作为次级文字，主要文案使用用户动作。
- **帮助**：将屏厂初始化表和通用 SPI 桥配置边界说清楚，不再复制所有桥说明。
- **刷屏**：预览是视觉焦点；把源选择／图案和发送参数分两层，保持图像比例，不用过多外框。
- **面板初始化**：解析摘要、错误、命令表相邻；允许用户原表忠实重放，不能为了“兜底”偷偷补命令。
- **读回**：寄存器读取与连续 RAM 读回分成两个区域；390 像素下当前参数行被裁切，需要换行或区域内明确横向滚动。桌面未观察到整页溢出。

### 4.10 SPI 转发

- 已检查：ASCII／ANSI／HEX，SPI 从机配置和 CDC 接收。
- 功能：计数里区分 SPI 接收、转入 CDC、丢弃、FIFO／DMA 错误是合理设计。
- 视觉：沿用 RTT 转发的编号与双连接状态，把“正在运行但未打开接收口”显式呈现；主要显示接收／转发／丢弃三个指标，缓冲细项放可展开详情。
- 三种接收模式与串口、RTT 转发保持同一套按钮顺序和记录反馈。

### 4.11 SWO 执行轨迹

- 已检查：录制／分析、默认离线界面；相关离线录制、时钟、恢复、导出测试已执行。
- **录制**：当前编号流程有价值，但侧栏过长。第一屏优先 ELF、串口、识别到的时钟与开始条件；复杂带宽预算、事件速率可展开。采用“缺哪一步”提示解释禁用按钮。
- **分析**：把导入记录、加载示例、补充 ELF／源码分为三种清楚入口；结果摘要优先 PC 数、缺口和映射覆盖。源码与事件列表的空态应提供下一步。
- 视觉：PC 区间、播放条与筛选不要同样抢眼；当前游标与选中源码使用统一强调色。保留“采样不能还原逐指令轨迹”的边界说明，但不重复占据多个区域。

### 4.12 ETM 执行轨迹

- 已实际打开：调试／时钟／采集／文件；执行流／调用统计／火焰图／热点／ETMv4 包／可信区段；火焰图执行顺序与调用权重。
- **调试**：四步流程清楚。当前 ELF、目标连接、起点断点应有紧凑就绪摘要；未连时的禁用状态合理。
- **时钟**：突出已识别、用户填写、已核对三类值。保留 CPU 与 Trace 时钟分别核对，不能合成一个值。
- **采集**：Kingst、采样参数和联动采集入口保持连续；失败展示阶段与可重试动作。
- **文件**：历史记录、可重解码包与普通导出分别说明用途；默认格式不要掩盖原始记录的保留。
- **执行流**：Timeline、执行列表、源码配对有效；行选中与源码高亮应一致。提供收起 Timeline 的轻量入口，已有能力可保留。
- **调用统计**：列标题标明“路径记录／实际调用”的区别；点击函数后的筛选状态需要明显、可一键清除。
- **火焰图**：执行顺序和调用权重是不同解释，保留两个模式，靠近模式说明横轴含义；不要把执行序号误标成物理时间。
- **热点**：可加相对占比条，保留绝对记录数与未知状态；与 SWO 热点统一阅读习惯。
- **ETMv4 包**：作为专家视图保留；偏移、长度、包内容等宽，原始字节的查看入口比只靠悬停更易发现。
- **可信区段**：不只用黄色列表；增加各类问题计数及筛选，保持捕获边界、未知条件、真实包错误的区别。
- 当前静态服务器下的服务缺失提示能够呈现；本地服务正常时 iframe 已实测加载。旧报告中的重试／生命周期结论未直接照搬，本轮相关回归通过。

### 4.13 USB→I2C

- 已检查：侧栏连接／总线／诊断／帮助；扫描总线／命令表／寄存器／脚本／实时值。
- **连接**：提供授权／已连接／桥已使能的连续状态，保持模拟入口。
- **总线**：时钟与超时值用清楚的单位；读回实际配置与待编辑值区分。
- **诊断**：总线恢复、接线自检和现场快照按作用分组，不与常规数据发送混在一起。
- **帮助**：把接线、电平、扫描和 repeated-start 示例按任务整理。
- **扫描总线**：现有地址矩阵有效，ACK 图例应同时包含文字，扫描中的进度明显；器件列表应能直达命令／寄存器操作。
- **命令表**：突出器件地址、子地址、写入和读取长度的区别；错误在本行呈现。
- **寄存器**：与 SPI 寄存器页采用相同的修改标记、提交与回读布局。
- **脚本**：运行状态与停止入口在所有工作区都应可见；保持真实周期由探针驱动。
- **实时值**：与 SPI 统一单位、频率和曲线格式；无数据时提供可直接载入的解码示例。

### 4.14 USB→ADC/DAC

- 已检查：ADC 示波器／DAC 信号发生器，预览和禁用状态。
- **ADC**：优先修复 F03。采样配置、显示缩放、触发与导出应分组；冻结与停止要有不同状态。量测结果可保留，但以当前窗口为计算范围的说明靠近读数。
- **DAC**：当前硬件不支持时，把“预览／导出可用，物理输出不可用”放在 Tab 标题下；波形参数分为形状、频率、幅度／偏置、采样表高级参数，减少重复电压字段同时争夺注意力。已有预览不启动硬件输出的边界清楚，应保留。
- 视觉：ADC 波形是主视觉；DAC 默认预览线对比度可略提高，辅助刻度和实际频率／量化误差摘要更易阅读。

### 4.15 工程生成

- 已检查：工程文件／调试参数／本地桥／ETM 桥；6 个工程文件、7 个本地桥文件、5 个 ETM 启动文件的预览。
- **工程文件**：载入项目后展示器件／地址／文件数量；二进制 `test_sram.bin` 继续用 HEX 预览，标明用途和大小。
- **调试参数**：参数表可保留“点值复制”，但增加可发现的复制图标／短提示；默认值和项目解析值区分。
- **本地桥**：常用端口、目标和后端在前，安装与下载高级配置折叠；生成文件与完整运行时包的差异写在下载按钮附近。
- **ETM 桥**：“下载完整包”作为主要操作，“仅下载启动文件”作为次要操作；现有说明基本完整，可缩短首屏文字。避免用户只下载启动文件后认为缺少运行时是软件 bug。
- **文件预览 Tab**：18 项均可切换。390 像素下末尾文件按钮超出容器，增加可见横向滚动或文件下拉；预览切换不必每次重建全部按钮，便于保留焦点。
