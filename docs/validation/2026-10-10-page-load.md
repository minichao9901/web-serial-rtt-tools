# 在线工作台加载耗时与优化

日期：2026-10-10。用户反馈 GitHub Pages 首次加载约 30 秒。本轮在当前电脑的 Chrome 测试浏览器中复现，未连接探针或操作目标板。

## 线上实测与定位

测量从导航开始到加载遮罩移除、工具可用；不使用 `load` 事件作为唯一依据，因为入口动态导入时，`load` 可能早于应用初始化。每轮使用独立测试页并置于前台，避免后台标签页的动画帧节流干扰。

| 场景 | 工具可用时间 | JS 请求数 | 结果 |
|---|---:|---:|---|
| GitHub Pages 冷启动，关闭并清除缓存 | **49.072 秒** | 158 | 无请求失败、无页面异常 |
| 同一线上页面，缓存命中 | **0.153 秒** | 158（绝大部分命中缓存） | 无页面异常 |
| 本地源码，关闭缓存 | 0.709 / 0.605 秒 | 158 | 两次均正常 |

线上冷启动资源传输约 1.077 MB、解压后约 2.824 MB；使用 HTTP/2。多个只有几 KB 的模块请求耗时约 22 秒，模块依赖需要逐层发现。源码入口包含 155 个静态模块，不能再用旧提示中的“20 多个模块”描述。

缓存命中及本地结果表明，主要瓶颈是大量网络请求和依赖发现等待，页面本身的初始化开销不是 30～50 秒。该电脑一次冷启动的 49 秒不代表所有网络的固定耗时。

## 实现

- 线上静态站默认加载 `app/site/main.js`，将 155 个静态模块合并；本地 localhost / 127.0.0.1 / IPv6 loopback 仍直接加载源码，无需构建即可编辑。
- HTML 提前预加载所选入口，合并脚本 URL 带内容哈希，避免更新后继续命中旧版本的同名脚本。
- 保留源模块的 URL 基准，SWO 解码 / 导出 Worker、ADC Worker、内置 SVD 和实测示例继续从原路径加载。调试器的 CFI、局部变量等动态模块仍按需加载。
- 合并文件随仓库保存，适用于现有 GitHub Pages 分支静态发布；不要求修改 GitHub Actions 或服务器。
- 固定 esbuild 0.25.12 和依赖锁文件；`npm run build:web` 更新脚本及清单，`make check` / `npm run check:web` 检查源码、输出与 HTML 版本是否一致。
- 8 秒提示改为等待资源 / 检查网络，不再把慢加载直接归因于旧 JS 缓存。
- 初始化完成后立即移除遮罩，不再依赖 `requestAnimationFrame`；后台或最小化标签页的动画帧暂停也不会让遮罩一直留着。
- 源码与输出的文本哈希按 LF 规范化，已对 Git 中的 155 份 LF 源文件核对，避免 Windows CRLF / Linux LF 导致清单校验失败。

## 相同网络条件对比

Chrome CDP 模拟 **200 ms 延迟、8 Mbps 下载带宽**，本地测试服务对 HTML / JS / CSS 使用 gzip，全部关闭缓存。同一组源码、相同浏览器，交替测量两轮；这是受控对比，不是优化后 GitHub Pages 的实测。

| 模式 | 第一轮 | 第二轮 | JS 请求数 | 资源传输量 |
|---|---:|---:|---:|---:|
| 源码模块 | 6.779 秒 | 6.629 秒 | 158 | 1,095,455 B |
| 合并脚本 | 1.278 秒 | 1.236 秒 | 4 | 551,324 B |

平均工具可用耗时下降约 **81%**，资源传输量下降约 **50%**。4 个 JS 请求包含 xterm、fit addon、合并入口及非阻塞的代码版本检查。加上 2 个 CSS 共 6 个资源请求；不含 HTML 本身。最终带哈希的入口单独复测为 **1.272 秒**，无请求失败或页面异常。

## 发布后的真实线上结果

经用户确认后提交并推送：`2820af8` 为合并脚本，`1b0453f` 修正跨平台哈希，`5ee7e98` 修正后台遮罩。已核对 GitHub Pages HTML 中的脚本内容哈希，确认使用新入口；最终脚本 1,253,208 B。

| 真实 GitHub Pages 场景 | 优化前 | 优化后 |
|---|---:|---:|
| 冷启动，关闭并清除浏览器缓存 | 49.072 秒 | **13.862 秒** |
| 浏览器缓存命中 | 0.153 秒 | **0.092 秒** |
| JS 请求数（包括异步版本检查） | 158 | **4** |

首次发布后的冷启动还测得 15.031 秒、缓存命中 0.114 秒。最终冷启动无请求失败、无页面异常，资源传输 548 KB 左右。网络会波动，这些是该电脑的有限测量窗口；不能承诺所有网络固定耗时。受控对比仍约 1.2～1.3 秒，实际 GitHub Pages 冷启动更慢，剩余时间主要花在约 446 KB 压缩合并脚本的下载。

中间一次重测时，资源和初始化约 15 秒已完成，但后台标签页的动画帧暂停，导致 120 秒内遮罩未移除。该轮不计入网络耗时统计，也不掩盖为请求失败；由此发现并修复遮罩依赖动画帧的问题。修复后特意创建隐藏的后台测试页，本地合并版 **0.336 秒**完成初始化并移除遮罩，无页面异常。最终线上测试使用修复后的脚本，正常完成。

更新后首次使用建议强制刷新一次，以获取新版 HTML；之后正常刷新利用缓存。`?modules=source` 仍可强制使用源码入口进行排查。

## 功能验证

- 合并版真实页面内置 UI 自检：**25 / 25**，覆盖演示串口、HEX / 时间戳 / 收发、终端、页面入口及连接状态。
- 合并版 SWO 页面回归：**43 项通过**，覆盖计算器、64/128 周期、手动 / 自动匹配、导出、保存重载、源码定位和宽窄窗口。
- F103CB 实测离线示例：**8,432 PC 全部映射，未知 PC 为 0**，ELF 指纹一致，解码 Worker 路径正确。
- 完整文本导出：1,920,266 B，函数名称存在，导出 Worker 路径正确；内置 F103 SVD 加载成功。
- 源码语法、发布清单及 Markdown Liquid 检查通过；SWO 匹配逻辑回归通过。

以上是页面与离线功能检查，没有重测硬件传输性能。

## 复测

已有 CDP 测试浏览器（默认端口 9333）时：

```powershell
node tools/selftest/page-load-bench.mjs --url=https://minichao9901.github.io/web-serial-rtt-tools/index.html --runs=2 --warm --out=tmp/page-load-online.json
node tools/selftest/page-load-bench.mjs --url=http://127.0.0.1:8899/index.html --compare --runs=2 --latency=200 --mbps=8 --out=tmp/page-load-compare.json
node tools/selftest/page-load-bench.mjs --url=http://127.0.0.1:8899/index.html --mode=bundle --background --out=tmp/page-load-background.json
```

第二条使用本地服务的实际压缩策略；若服务不压缩，传输量和耗时会与上表不同。本地网页地址追加 `?modules=bundle` 可直接验证合并版，`?modules=source` 可强制使用源码。

摘要机器数据见 [page-load.json](2026-10-10-page-load.json)。
