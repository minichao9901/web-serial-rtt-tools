# HPM5301EVKLite 实机回归记录

日期：2026-10-10。探针连接 HPM5301EVKLite，目标识别为 HPM5301 / RISC-V，JTAG IDCODE 为 `0x1000563D`。SPI 测试按 PB10/11/12/13 一一连接并共地执行。

## RTT 与 J-Scope

RTT Viewer 测得 **44.2 KB/s**，错位读和溢出均为 0。RTT 转发测得页面 **1.384 MB/s**、探针侧 **1.381 MB/s**。10 秒录制收到 14.08 MB、文件 14.03 MB，一致性 **99.6%**，结束时写入积压 84 KB。

本轮 RTT 场景原始数据见 [campaign JSON](2026-10-10-hpm5301evklite-rtt-campaign.json)。

J-Scope 完成 1/2/3/4/8 个变量 × 2/5/10/20/30/50/100 µs，共 35 个 3 秒测试格。高采样率的结果如下；丢失率分母为收到样本加探针丢失、USB 丢失和序号缺口。

| 变量数 | 2 µs 实测 | 2 µs 总丢失率 | 零丢失的最小测试间隔 |
|---:|---:|---:|---:|
| 1 | 308.4 kHz | 39.12% | 20 µs |
| 2 | 60.4 kHz | 88.81% | 20 µs |
| 3 | 52.2 kHz | 90.19% | 20 µs |
| 4 | 45.9 kHz | 91.29% | 30 µs（20 µs 丢失 7.19%） |
| 8 | 31.1 kHz | 94.02% | 50 µs（30 µs 丢失 5.79%） |

低速格 1/2/3 个变量在 20 µs 起零丢；4 个变量需 30 µs，8 个变量需 50 µs。4 个变量 @10 µs 还出现 333 个 USB 丢样本。全部格子的样本数、实际速率、探针/USB/序号丢失和各自比例见 [J-Scope JSON](2026-10-10-hpm-5301evklite-jscope-matrix.json) 与 [CSV](2026-10-10-hpm-5301evklite-jscope-matrix.csv)。

## SPI DMA 速率与误码

目标 HPM5301 作 SPI2 从机、探针作 SPI2 主机，Mode 0 与 Mode 1 分别实测。目标从机配置与探针 SPI2 从机使用相同的 240 MHz 模块时钟、PB10 硬件 CS0、PB11 SCLK 输入、PB12 MISO、PB13 MOSI。每笔 DMA 传输回显上一笔 256 字节 MOSI，逐字节比较。探针提供的单笔时间来自硬件计时器；WebUSB 列包含浏览器逐笔命令开销。

| SPI 模式 | 实际 SCLK | 结果 | BER | 探针测得单笔总线速率 |
|---|---:|---:|---:|---:|
| Mode 0 | 10 MHz | 128/128 帧正确 | 0 ppm | 1.211 MB/s · 211.46 µs/帧 |
| Mode 0 | 20 MHz | 128/128 帧正确 | 0 ppm | 2.350 MB/s · 108.92 µs/帧 |
| Mode 0 | 24 MHz | 121/128 帧正确 | 26.7 ppm | 2.784 MB/s · 91.96 µs/帧 |
| Mode 0 | 30 MHz | 双帧同步有 1 bit 错误 | 488 ppm（同步帧） | 3.42 MB/s · 74.92 µs/帧 |
| Mode 0 | 40 MHz | 65/128 帧正确 | 240.3 ppm | 4.433 MB/s · 57.75 µs/帧 |
| Mode 0 | 60 MHz | 同步响应 BER 49.07% | 490,723 ppm | 5.66 MB/s · 45.17 µs/帧 |
| Mode 0 | 请求 75 MHz，实际 60 MHz | 同步响应 BER 49.37% | 493,652 ppm | 5.68 MB/s · 45.04 µs/帧 |
| Mode 1 | 20 MHz | 64/64 帧正确 | 0 ppm | 2.350 MB/s · 108.96 µs/帧 |
| Mode 1 | 24 MHz | 64/64 帧正确 | 0 ppm | 2.786 MB/s · 91.88 µs/帧 |
| Mode 1 | 30 MHz | 64/64 帧正确 | 0 ppm | 3.421 MB/s · 74.83 µs/帧 |
| Mode 1 | 40 MHz | 128/128 帧正确 | 0 ppm | 4.433 MB/s · 57.75 µs/帧 |
| Mode 1 | 60 MHz | 同步响应 BER 49.85% | 498,535 ppm | 5.55 MB/s · 46.13 µs/帧 |
| Mode 1 | 请求 75 MHz，实际 60 MHz | 同步响应 BER 50.29% | 502,930 ppm | 5.42 MB/s · 47.21 µs/帧 |

**本轮回显靶的已通过档位：Mode 0 /20 MHz、Mode 1 /40 MHz，各执行 128 帧无比较错误。60 MHz 的返回回显与发送模式不一致，原因尚未定位；75 MHz 请求实际落在 60 MHz。** 这些结果不能作为探针或 HPM5301 SPI 硬件的速率上限。回显校验同时经过 MOSI 输入、目标 TX DMA、MISO 输出和探针主机接收，尚未分别核对各阶段；失步时约 50% 的位比较差异也不能直接称为物理 BER。

2026-10-10 补查历史：相同 240 MHz 模块时钟、Mode 0 下，探针从机曾完整接收 H743 标称 60/66/67 MHz 连续流，分别达到 7.532/8.286/8.412 MB/s，15 秒窗口中载荷位错误、缺帧及探针丢弃均为 0。早期 HPM 主机→探针从机仅配置固定 10 MHz；后续改用连续 TX-only 循环 word DMA 并扫速，已验证到 80 MHz、10.00 MB/s。独立 Probe TX-only → HPM RX-only 的 MOSI 校验也在 60 MHz 通过，完整回显的问题仍未确认。详见 [历史对照与诊断修正](2026-10-10-hpm-spi-history-comparison.md)。

额外以 20 MHz、一次提交 16 笔的紧密突发压力测试，只有 8/128 帧通过。当前回环靶子每笔 DMA 完成后重新挂下一笔，无法保证这种连续突发间隔。它与下面“目标主机连续发送、探针使用循环 DMA 从机”的 SPI→CDC 测试路径不同；持续转发结果以该循环 DMA 测试为准。压力数据见 [16 笔突发测试](2026-10-10-hpm5301-spi-dma-20-batch16.json)。

全双工 20/24/40/60/75 MHz 结果见 [对应 JSON](2026-10-10-hpm5301-spi-dma-10-20-final.json)、[24 MHz](2026-10-10-hpm5301-spi-dma-24-final.json)、[40 MHz](2026-10-10-hpm5301-spi-dma-40-final.json)、[60 MHz](2026-10-10-hpm5301-spi-dma-60-final.json) 和 [75 MHz 请求](2026-10-10-hpm5301-spi-dma-75-final.json)。Mode 1 的连续测试另见 [20/24/30 MHz](2026-10-10-hpm5301-spi-mode1.json)、[40 MHz 128 帧](2026-10-10-hpm5301-spi-mode1-40-final.json) 与 [60/75 MHz](2026-10-10-hpm5301-spi-mode1-high.json)。

## SPI 转发：目标主机、探针从机

目标 HPM5301 使用 SPI2 主机 DMA，以 10 MHz、Mode 0 连续发送带序号和校验模式的 64 字节帧；探针 SPI2 从机接收后经 USB CDC 转发。10 秒测得 **1.201 MB/s**，解析 187,886 帧，无序号缺口、无坏帧；84,172,928 个 payload bit 中误码为 0。窗口内探针 received/forwarded 均增加 12,023,839 字节，丢弃、FIFO overflow、DMA error 均为 0。停止采集时 DMA 环尾部另有 12 字节被丢弃，这 12 字节落在测量窗口之后。

结果见 [SPI→CDC JSON](2026-10-10-hpm5301-spi-cdc.json)。

后续将目标改为 **32 KiB TX-only 循环 word DMA、持续 CS、变化载荷与连续序号**，完成同方向扫速。最终验收档 **80 MHz** 实收 **10.00 MB/s**，10.011 秒收到 100,105,564 字节、1,564,150 帧；比较 700,739,200 个载荷位，位错误、缺帧、失步、探针丢弃及 FIFO/DMA 错误均为 0。测试使用 64 KiB WebSerial 接收缓冲，默认 4 KiB 缓冲的 80 MHz 表现未重新验证。83.333 MHz 的 10 秒窗口通过，但 30 秒延长测试有丢弃，因此本轮只验收至 80 MHz，并按用户要求停止继续探索。详见 [边界测试 JSON](2026-10-10-hpm-spi-rx-boundary.json) 与 [完整诊断说明](2026-10-10-hpm-spi-history-comparison.md)。

复测入口为 `make spi-cdc-hpm5301-master-hw`，默认测试 20/40/60/80 MHz 各 10 秒，输出到 `tmp/hpm5301-spi-cdc-sweep.json`，不覆盖本次归档记录。

## 调试器与异常

网页 RISC-V 调试器实测 **61 项通过、0 项失败**。其中 19 条指令级单步地址与独立 GDB oracle 逐项一致；函数/文件行断点、8 个硬件触发器、复位重跑、40 轮停走压力、嵌套结构体和位域读取均通过。GDB 逐字段核对结构体位域布局一致。

异常测试在目标上注入非法指令并由硬件断点停在现场：固件记录 `mcause=2`、`mepc=0x80005298`、`mtval=0xFFFFFFFF`；网页异常面板读到相同 CSR 并解码为非法指令。完整网页回归与 GDB 对照摘要见 [调试结果 JSON](2026-10-10-hpm5301-debug.json)，独立 GDB 单步与位域 oracle 见 [GDB oracle JSON](2026-10-10-hpm5301-gdb-oracle.json)。

另外，当前环境里的 RISC-V GDB 不带 Python，因此独立 CFI 栈帧 oracle 脚本无法运行；本次 GDB 对照覆盖断点地址、19 条指令级单步和位域解析，未把 GDB 栈帧变量比较计入通过项。
