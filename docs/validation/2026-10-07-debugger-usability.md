# 6800EVK 调试器交互修复验收

日期：2026-10-07。浏览器使用本地 Web 页面，WebUSB RISC-V/JTAG 10 MHz，目标为在线 HPM6800EVK，固件 ELF 为 `lwip_tcpecho` 的 flash/SDRAM/XIP debug 版本。

## 修复内容

- 手动执行命令或点击调试动作时恢复输出跟随，并在动作结束后滚到最终结果。后台日志仍保留用户翻看历史时的位置。
- `n` 在函数最后一条行号记录处执行已有的跳出流程。没有当前行号或可靠函数信息时仍明确报错。
- 命令中的 PC 回显使用本次停止地址，避免全寄存器缓存尚未刷新时显示上一次的 PC。
- 调试器 RTT 面板增加“清屏”，只清显示内容，保留 RTT 对象、轮询与目标环缓冲区状态。

## 真机结果

首先直接从用户报错的位置验证：`trace_log_init` 的 `trace_log.c:28`，PC 为 `0x80007bfe`。此时 `ra` 也是 `0x80007bfe`，是内部调用留下的返回地址，不能直接作为本函数的返回地址。

修复后复用跳出流程，执行 `nop / lw ra / add sp / ret` 四条指令，返回 `main` 的 `lwip.c:33`，PC 为 `0x80007916`。

随后重新加载 Web 并恢复连接、ELF、146 个源码文件及两个用户断点，连续执行三轮：

1. 复位并停，继续至 `main` 断点。
2. 继续至 `trace_log_init` 断点。
3. 按 `n` 依次停到 `0x80007bf6`、`0x80007bfa`、`0x80007bfe`。
4. 前两轮再次执行 `n`，第三轮点击“跳过”，均返回 `0x80007916` / `main` 第 33 行。

每一步的 PC 回显与硬件直接读取一致；两个用户断点均保留，无临时断点残留或传输故障。

真页面中翻到历史后执行 `r pc`，输出回到最底部。RTT 实际定位成功，点击“清屏”后显示为空且 RTT 实例仍然有效。验收结束停在 `main` 第 33 行，RTT 已停止，源码目录和断点保留。

- `dbg-view-lock.test.mjs`、`dbg-riscv-memory.test.mjs`：通过，独占访问、源码刷新及已有 SDRAM 防护保持有效。
