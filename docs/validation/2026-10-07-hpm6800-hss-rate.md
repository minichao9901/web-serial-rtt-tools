# 6800EVK JScope 高速采样复测与优化

2026-10-07，HPM6800EVK/HPM6880，真实浏览器 HID 控制、WebUSB DATA、绘图开启。测试暂停 CDC，采样时不并行运行 OpenOCD。每段预热 0.5 s；基线正式窗口 5 s，优化后和同固件开关对照窗口 8 s。计数采用 action 11 的原子完整 32 位指标，读取探针 24 MHz 时间计算窗口长度，不用截断的 STAT 或主机计时推算探针速率。

## 探针瓶颈与批次优化

单字 M0 约 2.966 µs；它只测读取，不包含主循环服务、组帧和 USB。旧 RISC-V 路径每样本回到主循环，极限实得约 283～285 kHz。新路径仅在显式 FAST_BATCH、单个 4 B 对齐 span、周期 ≤6 µs 时每次最多采 16 拍；仍在包边界返回，保留中断、STOP/复位/配置检查和每 32 次 held read 的 SBCS 检查。SWD 的原批次条件保持不变。

| 单字周期 | 基线实得 kHz / 跳拍率 | 优化后实得 kHz / 跳拍率 |
| --- | --- | --- |
| 2 µs（名义 500 kHz） | 282.601 / 43.4798% | 305.206 / 38.9588% |
| 3.25 µs（307.692 kHz） | 285.450 / 7.22877% | 302.746 / 1.60752% |
| 4 µs（250 kHz） | 249.349 / 0.260588% | 249.519 / 0.192202% |
| 5 µs（200 kHz） | 199.994 / 0.0027955% | 199.995 / 0.0027472% |
| 6 µs（166.667 kHz） | 166.665 / 0.0009585% | 166.665 / 0.0011244% |
| 10 µs（100 kHz） | 100.000 / 0% | 100.000 / 0.0002499% |

不同窗口的小计数差异不代表慢档改善或退化。以上正式窗口 USB 丢样、读错、DAP 让路均为 0。高档改善用同一新固件开关再次确认：3.25 µs 关闭批次实得 288.457 kHz、跳拍 6.25163%；开启实得 302.760 kHz、跳拍 1.60297%。因此主循环开销确实是高档限制之一；500 kHz 超出当前 JTAG 读取能力，增加浏览器缓冲不能消除这部分跳拍。

## 浏览器瓶颈与预读窗口

8 个连续 u32、40 µs 周期：读取 M0 约 31.03～31.07 µs，探针跳拍为 0，但旧网页正式窗口 USB 丢样 989（0.79056%）。每 DATA 包仅 15 个样本，线上流量约 `25000 × 512 / 15 = 853333 B/s`。原 1 MB/s 阈值未扩大窗口，3×4096 B 仅覆盖约 14.4 ms；实测绘图/解码停顿可到 25 ms，后续捕捉到约 52 ms 停顿。

新规则：若 12 KiB 不足以覆盖 30 ms，改为每读 8192 B、并发数 `clamp(ceil(线上流量 × 0.080 / 8192), 6, 16)`。约 0.85 MB/s 用 9 条，预读 72 KiB，上限 128 KiB；显式自定义窗口不改动。保持按提交顺序交付、消费前重新发读、停止后退役残留请求。暂时扩大到 6×8192 B 的中间版本仍有丢样，未作为最终方案。

## 真正坏值与跨字段相位差

所有速率窗口检查 u_hi 固定高 16 位和计数前进方向，坏值/倒序/包倒序为 0。最终 8 通道窗口另逐点核对正弦、三角、方波、ramp 与 tick±1 的契约，超出契约的值为 0。LFSR 没有逐点重建校验，不能将结果称作 8 通道每个比特均已证明正确。基线只核对了 u_hi，没有保存全部原始通道值供事后重检。

高速块追加验证：单字 tick 实得 305.240 kHz；tick+正弦双通道在 20 µs/50 kHz 和 25 µs/40 kHz 的正式窗口，探针跳拍、USB 丢样、读错均为 0，分别检查 431582、345154 帧。

该块每 5 µs 更新，两次 SBA 总线读之间目标仍在运行。双通道 M0 约 15.8 µs，正弦值通常对应 tick+1；不能要求同帧同时取值。检查保留相位分布，用 `ceil(M0/5)+1=5` 拍作为**诊断预算**，并单独记录超过常见两拍范围的偏差。50 kHz 有 3 帧（0.000695%）相差 3/4 拍，40 kHz 有 3 帧（0.000869%）；每个正弦值仍符合源表，未发现超出该预算的值。最初按最多两拍检验出现的两帧失败保留在 JSON 的 `smoothStrictPair`，未隐藏。平均 M0 不是中断延迟上界，这些相位偏差的确切中断来源没有做硬件时序追踪；不能把预算内所有帧解释为已证明原子一致。

## 计算公式

更新 JTAG 经验锚点：单字 2.97 µs；块读独立扫描锚点 2.59 µs，连续 8 字 `(8+4)×2.59=31.08 µs`。先前直接拿单字 3.17 当块路径扫描成本会估成 38.04 µs，与本次约 31.07 µs 不符。保留 N+4 扫描数、地址对齐、间隙和多个 span 的成本；默认 DMI delay=8，换目标总线/延迟应重新标定。

建议周期仍 `max(3, ceil(M0×1.5))`，当前单字为 5 µs、8 连续字为 47 µs，双通道高速块约 24 µs。5 µs 的微量跳拍说明建议是起点，不是零跳拍保证。读取耗时的倒数单独标为读取上界，用户更快的请求保留并警告，2 µs 硬件下限仍明确归一化。需要接近无跳拍时应看真实计数并适当降低速率；单字 500 kHz 不能靠公式兑现。
