还没读

          
点表里任意字节 → 8 个 bit 的开关板（点一下就翻转，与原值不同的位套黄框；也能直接敲十六进制）。
            读到的值 = 器件现值，只有点「只写改动 / 整块写回」才真的发 SPI。

            ⚠️ SPI 没有统一约定，三个最常错的地方就在上面那排字段：读命令怎么带寄存器号、
            要不要 dummy（MPU-9250/LSM6DS3/BMP280/ADXL345 都是 0 —— 网上"BMP280 要 dummy"是把它和 BMP380 搞混了）、多字节读是否自增。
            假探针切到「寄存器器件」（BMP280 风格）时，档位选 BMP280 就对得上。

探针 · SPI转发
        

        
未连接

        

        
        
        

        
等待连接探针

        
接线与资源
复用 SPI2：PB10 CS、PB11 SCK、PB13 MOSI；PB12 MISO 可不接。主机与探针共地，CS 低有效，8 位。时钟由外部 SPI 主机提供。
SPI 从机与 USB→SPI/QSPI、SPI/QSPI 屏及 ADC 共用缓冲与引脚。CDC 与 UART、RTT 转发共用同一个串口，启动时切换数据源。先打开下方接收串口，再启动外部发送。
连接时自动复用唯一已授权的探针。要更换设备，请先关闭探针，再手动选择；接收串口独立管理。

      

      

        接收（探针的 CDC 口）
        
        

          
          
        

        
        

          
          
        

        
先启动转发，再启动外部 SPI 主机。重启转发前先停止主机发送，让 CS 回到高电平。

        
启动转发后点「连接」打开探针那个 CDC 口，数据就会出现在右边。

SWO 使用帮助

  
接线与上手目标时钟带宽计算探针匹配文件与示例

  
1. 接线与上手
连接目标 PB3 / SWO → 探针 PB07 / VCOM RX，并连接 SWD 和 GND。使用 NRZ / 8N1。选择 VCOM、授权探针时钟、识别目标；在“分析”载入匹配的 ELF 与源码，再回到“录制”开始。停止后自动分析并恢复 Trace / 探针接收配置。

  
2. CPU、Trace 与外部晶振
CPU 频率决定 PC 采样率和周期时间；Trace 输入频率决定 SWO 编码器的分频。读取 RCC 可以得到时钟源和 PLL / 总线分频，板上外部晶振或有源时钟的频率仍需提供。标注“自动推算”表示根据配置计算，不是测量晶振。
F103 / F407 的 SWO 输入来自 HCLK，与 CPU 频率相同。H743 / H7B0 在 PLL 模式下使用 PLL1 R 输出作为 SWO 输入，CPU 使用 PLL1 P 输出并另经核心分频；不能直接拿 CPU 或 HCLK 替代。页面读取 PLL1 的 M、N、FRACN、P、R 和核心分频，分别计算两者。调试组件的总线时钟和 SWO 引脚编码时钟也需区分。常见型号的 DEV_ID 可能由多个芯片共用，页面显示型号组，不能保证识别到封装和完整料号。未知型号只识别内核并提示未适配，不套用 F103 配置。
本页不修改目标 PLL、核心分频和 SysTick。目标程序需要保持录制期间的时钟稳定；改变时钟后应停止并重新识别。

  
3. 从采样密度计算带宽
PC/s = CPU Hz ÷ PC 周期间隔
PC 字节/s ≈ PC/s × (无时间戳 5 B；带时间戳约 9 B)
异常字节/s = 进入 / 退出事件总数/s × 3 B
ITM 字节/s ≈ 有效载荷字节/s × 2（按单字节包估算）
所需 baud = (PC + 异常 + ITM + 其他 字节/s) × 10 ÷ (1 − 余量)
目标实际 SWO baud = Trace 输入 Hz ÷ (ACPR / CODR + 1)
72 MHz ÷64 = 1,125,000 PC/s。仅 5 B 的 PC 包就需 56.25 Mbaud，超过探针 30 Mbaud。间隔越小，采样越密，但需更多带宽，依然不能还原 ETM 的逐指令分支流。DWT 合法间隔是 64 或 1024 周期的 1–16 倍；输入期望 PC/s 时选择不超过期望值的合法采样率。
时间戳长度和频率可变，实际带宽还包含同步、睡眠等包；这里给出规划估算，溢出和接收错误仍以实测为准。

  
4. 探针接收波特率与时钟
UART Hz = 选定 PLL 输出 Hz ÷ SYSCTL 分频
probe baud = UART Hz ÷ OSR ÷ UART DIV
误差 % = |probe baud − 目标 SWO baud| ÷ 目标 SWO baud × 100%
自动匹配先选择当前时钟源与分频；必要时调整 PLL1。默认 UART 240 MHz，最高 30 Mbaud。软件不会调整承载 CPU 的 PLL0；PLL1 调整须经过共享消费者检查，最终以探针回读为准。下方显示实际使用 PLL0 或 PLL1 的完整路径。“授权时钟”是浏览器对探针 HID 接口的访问授权。

  
尚无匹配配置

  
5. 记录、ELF、源码与实测示例
“打开记录”打开自己的 .swopc 或原始 .bin；“载入配套实测示例”同时载入仓库内的实测记录、匹配 ELF 和源码，不连接硬件。.swopc 保存采样配置、ELF 指纹和错误信息；原始 .bin 只有数据，只有确定数据包边界时才勾选导入选项。
完整 .c 保留源码行和采样注释；“导出简化.c”只保留 C/C++ 源码，去掉注释，合并连续重复的行及代码片段，缺口以空行分开。两种导出均重新解码全部原始记录，不受区间和 250000 条事件上限影响。简化导出需匹配的 ELF 与源码；未采样代码不会补齐，文件用于阅读而非编译。

RTT 使用要点

  
    
    
  • 固件里必须编进了 SEGGER RTT（SEGGER_RTT_Init() 会被自动调用）。
    • 
    
  • 控制块地址优先用 ELF 符号（载入 .elf 最稳），否则用「扫描控制块」在 RAM 里找 "SEGGER RTT"。
    • 
    
  • 同一个探针不能被两个程序同时占用：OpenOCD / pyOCD / J-Link 开着时，先关掉它们。
    • 
    
  • RTT 不重传：目标写太快会覆盖/丢弃还没读走的数据。「缓冲高位」的次数和峰值水位是最实用的
      过载信号（≥75% 就算高位）；「溢出丢弃」只在主机侧读指针落后时才算得出来 —— 两个数字都当下限看。
      主机读速受调试器限制（OpenOCD RPC 实测 ~17 KB/s），大流量场景优先用 WebUSB 探针。

RTT → CDC 转发（「RTT 转发」那一页，akaLinkPro 探针）

  
    
    
  • 让探针自己通过 SWD 轮询目标的 RTT 控制块、把数据塞进它的 CDC 串口 —— 主机只要读一个 COM 口，
        比主机侧轮询快得多（本机实测 2.4 MB/s）。
    • 
    
  • 这一页是纯输出：只有接收（ASCII / ANSI / HEX、时间戳、暂停、保存数据、记录到文件），没有发送。
    •

    •

  • ⚠️ Cortex-M7（H743 / H7B3…）要给 AXI SRAM 地址（如 0x24000000）：DTCM 探针读不到。
    •
